## Description

Connects D&D elapsed-time consumers to the single base-application world clock installed in the
D&D state space. It does not create campaign time, wall-clock time, or a second clock owner.

## Instructions

1. Bind the exact active world as role `world`. Resolve `dnd2024.game.core.world.root` and
   `dnd2024.game.core.world.clock` through the declared `game` base application.
2. To pass explicit in-world time, execute `dnd2024.mechanic.world.clock.advance` with exactly
   `{ "minutes": n }`, where `n` is an integer from 1 through 1,440.
3. Elapsed-time consumers read `calendarId`, `currentMinute`, and `revision` from that projected
   clock. They never accept any of those values from request input.
4. Preserve calendar identity, advance the minute monotonically, and increment the embedded
   revision once. Let application execution reject stale persisted component evidence.

## Constraints

- No D&D-owned or campaign-owned duplicate clock is permitted.
- Do not infer elapsed time from sessions, recaps, map clicks, real time, or narration.
- Invalid, backward, overflowed, corrupt, non-closed, or stale changes make no mutation.
- Replay of a committed operation returns its prior result and never advances time twice.
- Reactions, expirations, rest completion, downtime completion, and notifications remain with
  their owning mechanics and later event/timing gates.
