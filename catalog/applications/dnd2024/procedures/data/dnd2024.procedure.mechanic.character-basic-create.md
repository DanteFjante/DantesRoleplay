## Description

Creates one deliberately incomplete but mechanically honest selected SRD background plus selected
SRD class level-1 actor. The operation derives core state from active source-bound definitions,
persists the background Origin Feat and class level-1 features as identity-only grants, applies
exact fixed proficiency and armor-training membership state, records every deferred
entitlement, and attaches the new actor to the bound active world in one application transaction.
When the exact background-and-class cash alternative is selected, that transaction also creates
and contains one physical Gold Piece stack derived from the bound source definitions.

## Instructions

1. Bind exactly the active world, Standard Array policy, one active SRD background with matching
   ability/profile source, selected species, and one active class with matching progression/profile
   source. When the cash alternative is requested, also bind the optional `currency` role to the
   exact canonical Gold Piece definition declared by the class profile. Accept only a host-reserved `actor.*` ID, display name, ability child input,
   species-selection child input, an optional exact `originChoices` object, and optional
   `classToolChoices` and `equipmentChoices`. The equipment choice, when present, is exactly
   `{background:"cash",class:"cash"}`; no amount, item ID, definition ID, stack key, slot, source,
   effect, or pending entry is caller-authored. When present, origin choices
   contains two distinct non-Common Standard languages and, only for a selectable-tool background,
   its exact canonical tool choice. Class tool choices contain exactly the distinct canonical
   tools allowed by the selected class profile: three Musical Instruments for Bard or one
   Artisan's Tool or Musical Instrument for Monk. Reject that property for any other class.
2. Compose the accepted ability, species-selection, and class-progression readers. Reject any child
   failure, effects, malformed data, source mismatch, inactive definition, or unexpected ID.
3. Derive level-1 Hit Points as the selected class Hit Die maximum plus the Constitution modifier
   (minimum 1) and unequipped Armor Class as 10 plus the Dexterity modifier. Apply the background's
   two fixed skills, an exact non-duplicate legal class-skill set, class saves, Common, all fixed
   background/class tools, complete weapon categories, and any Finesse/Light-qualified Martial
   membership declared by the class. If origin choices are supplied, apply the selected languages and background tool and
   store those selections; otherwise retain their pending entries. If class tool choices are
   supplied, union them into tool membership, store their canonical selection, and remove only that
   class-owned pending choice; otherwise retain it.
4. Derive `dnd2024.character-feature-grants` only from the selected background profile and the
   effect-free class-progression child. Record exact declaring-owner/source provenance and the
   Origin configuration or class level. A grant proves identity only. Keep all unresolved behavior
   pending, but for Alert use only `behavior:initiative-swap`: its optional Initiative Proficiency
   is implemented by the separate Initiative owner and must not remain mislabeled wholly pending.
5. Store the complete known `dnd2024.creature.proficiencies` category set from the selected class profile,
   including an empty known set, with the canonical Armor Training rule source. Do not infer an
   equipped-armor consequence.
6. If exact cash equipment choices are supplied, derive total GP from the background's declared
   cash alternative plus the class's declared cash alternative. Derive one bounded deterministic
   item ID from the reserved actor ID, record `selections.startingEquipmentChoices` and the one
   `createdItemIds` entry, and remove only the background and class equipment deferrals. Create the
   item with `dnd2024.core.definition-link` and `dnd2024.item.quantity`, then move it under the actor in
   `inventory.currency`. If equipment choices are omitted, create no currency and retain both
   equipment deferrals.
7. Create the actor, optional currency stack, containment, and campaign participation atomically
   through typed effects. Store other core
   state in its normal component and store only selections/applied IDs/pending evidence in
   `dnd2024.character-creation-record`. Use D&D-owned participation relationship kinds because
   relationship IDs are scoped to the active application state space.
8. Keep property-qualified Martial attack enforcement pending until weapon profiles expose
   canonical properties. Treat every unresolved entry as informational denial: it grants no feature behavior, trait, proficiency,
   equipment, resource, spell, language, tool, or action.

## Constraints

- `basic-playable` never means source-complete.
- The caller never supplies final scores, modifiers, HP, AC, Speed, level, proficiencies, effects,
  merged proficiency state, pending entries, participation identity/status, source references, or
  audit identity.
- The mechanic is the D&D rule owner; the generic action runner is the sole transaction, replay,
  rollback, and audit owner.
- Exact replay returns the prior result without creating another currency stack. Any late failure
  rolls back the actor, currency item, item components, containment, participation, and
  relationships together.
- `dnd2024.campaign.has-character-participation` and
  `dnd2024.campaign.character-participation.for-actor` carry exact `{}` payloads and preserve C15's
  world-to-participation-to-actor graph without creating a cross-application relationship ID.
- A duplicate actor/item/participation, inactive world, stale content, partial/non-cash/extra
  equipment choice, missing/wrong/corrupt currency role, invalid cash declaration, invalid request,
  or any late component/link failure leaves no actor, currency, containment, participation,
  component, or relationship behind.
- This procedure does not resolve species traits, Alert Initiative Swap, other Origin-feat
  behavior, class-feature behavior,
  equipped-armor/training consequences, background/class equipment packages, individual gear
  choices, packs or containers, auto-equip, baseline Armor Class changes, encumbrance consequences,
  buying or selling, currency exchange, class/feature language choices, tool behavior,
  restricted-Martial attack enforcement, spellcasting, rest completion, or advancement.
