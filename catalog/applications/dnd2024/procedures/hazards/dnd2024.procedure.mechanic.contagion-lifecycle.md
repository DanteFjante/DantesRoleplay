## Description

Record explicit exposure or transmission, progress incubation, and recover one source-backed
contagion while keeping narrative proximity separate from mechanical infection.

## Instructions

1. Call `dnd2024.mechanic.contagion.expose` only when an authorized source, target, and exact authored
   transmission event are known.
2. Call `dnd2024.mechanic.contagion.transmit` only from a named active source application and its
   verified source host. Never infer contact from conversation or co-location.
3. After an authorized clock-owning action reaches the due minute, call
   `dnd2024.mechanic.contagion.progress` with consequences that byte-match the definition.
4. Call `dnd2024.mechanic.contagion.recover` with the exact authored recovery activity and check.

## Constraints

- Contagion records and events use the affected subject as their audience scope and emit no public
  notification. A read view must still re-authorize before exposing them.
- Retry with the same idempotency key; do not create a second application or transmission.
- Missing transmission, incubation, effect, or recovery owners are stop conditions.
