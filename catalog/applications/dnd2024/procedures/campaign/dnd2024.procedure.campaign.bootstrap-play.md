## Description

Routes an AI or operator through the strict application actions needed to create a campaign and
make its first scene resumable. Each action owns one bounded change and the generic host validates
and transacts its effects.

## Instructions

Before starting the first session, read `dnd2024.procedure.campaign.party`. Treat the party as the
derived set of valid active campaign participations. Attach reviewed existing characters or create
explicitly simulated narrative companions through its governed actions, and verify the roster
before recording any participant in the opening situation.

For multi-chapter machine simulation, also read `dnd2024.procedure.campaign.machine-play` and build
its bounded action queue before the first mutation.

1. Inspect the exact World, starting location, and player-character actor. Never invent their IDs.
2. Write down the reviewed premise, 1-3 party goals, boundaries, opening arc, opening chapter,
   starting scene, and party/GM affordances. Hash the canonical reviewed campaign blueprint with
   SHA-256 and retain that fingerprint.
3. Execute `dnd2024.mechanic.campaign.create` with `world` and `location` roles.
4. Execute `dnd2024.mechanic.campaign.continuity.initialize` with the new `campaign` role.
5. Execute `dnd2024.mechanic.campaign.character.attach` once for each confirmed existing actor.
6. Execute `dnd2024.mechanic.campaign.current-scene.set` in `record` mode.
7. Execute `dnd2024.mechanic.campaign.scene-affordances.set`; suggestions are not player choices.
8. Execute `dnd2024.mechanic.campaign.session.first.start` only after the opening context is valid.
9. Record every user and assistant utterance through the durable play-conversation capability,
   bound to the campaign and session. Store newly established world truths through reviewed World
   synchronization before relying on them later.
10. Read back the campaign, arc, chapter, participation, scene, affordances, and session exactly.

## Constraints

- Use application ID `dnd2024` and its host-bound effective resolution fingerprint; never supply
  overlay-profile IDs.
- These actions operate on existing World and actor records. They do not silently create lore,
  characters, outcomes, player choices, or visits.
- Use intent planning when available. If planning is unavailable, submit a verified exact proposal
  for these registered actions and record the planner failure in system feedback.
- A machine simulation may choose setup text and GM framing, but it must label simulated dialogue
  and must not present simulated player decisions as user-authored history.
