## Description

Records reviewed associations from retained campaign records to already-relevant World entities and
captures the campaign's explicit aggregate memory of visiting one place.

## Instructions

1. End the session or conclude the arc through the existing campaign lifecycle owner.
2. Execute the matching reference mechanic once for each relevant entity already linked from the
   campaign by `game.core.campaign.references`.
3. When play establishes a visit, execute `dnd2024.mechanic.campaign.location-visit.record` with the
   campaign, its active World, the active referenced location, and the existing visit role only when
   updating it.
4. Supply only the bounded summary, party memory, optional GM context, and current/departed status.
   The mechanic derives the visit identity and reads time from the World clock.

## Constraints

- These mechanics never infer relevance, membership, location, or time.
- Reference actions never change recap, session, arc, or outcome components.
- Visit capture creates or replaces the component and its exact empty-data ownership/location edges
  atomically. It rejects ambiguous scope, the wrong existing record, a backward clock, duplicate
  creation, and malformed lifecycle state.
- Repeating the exact authorized operation is a replay, not another visit.
