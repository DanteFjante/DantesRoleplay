## Authoritative state and closed input

The executable path and pin are host-owned configuration. Browser callers have no input for either. The repository root still uses existing host resolution. The app-server receives only the existing fixed repository root and policy-derived read-only/no-network configuration; this slice sends no `thread/start` or `turn/start` request.

## Behavior, result, and typed effects

1. Composition reads the configured executable and reviewed exact pin.
2. The status probe invokes only `--version`, normalizes it, and reports ready only on exact equality.
3. The smoke starts JSONL app-server, sends `initialize` then `initialized`, verifies a response, and terminates it without a thread, turn, conversation record, approval, or model request.
4. Conversation behavior remains read-only, network-disabled, and explicit per-turn approval.

No database transaction or typed effect is introduced.

## Failure, replay, and rollback contract

- Missing/unstartable executable remains `CODEX_PROCESS_UNAVAILABLE`; a wrong version remains `CODEX_VERSION_MISMATCH`; neither starts a turn.
- Malformed, oversized, unsupported, or unexpected JSONL remains rejected by the existing bridge contracts.
- Initialization failure/timeout terminates the transient process and produces no durable record.
- If the generated descriptor or smoke conflicts with current process code, stop without changing compatibility behavior.
