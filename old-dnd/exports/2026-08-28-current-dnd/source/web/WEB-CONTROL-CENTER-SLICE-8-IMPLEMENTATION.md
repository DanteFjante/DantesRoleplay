## Confirmed Sol gate

The user's request to evaluate Slice 6 and continue with the next slice on **2026-08-24** confirms
the new `codex-bridge` process dependency, the migration below, and this read-only-first public
surface. The bridge is distinct from assistant-conversation persistence, the web adapter, local AI,
and the interaction-orchestration authority described by the AI implementation/dependency plan.

The reviewed protocol is Codex app-server v2 generated by `codex-cli 0.149.0-alpha.4.1`. The pinned
seam contains only stable `initialize`/`initialized`, `thread/start`, `thread/resume`, `turn/start`,
`turn/interrupt`, `item/agentMessage/delta`, `item/started`, `item/completed`, `turn/completed`, and
warning/error behavior. A different executable version reports unavailable until its seam is
reviewed and the pin is deliberately advanced.

## Process and sandbox contract

- The bridge starts a local `codex app-server --stdio` child process per active turn. It never opens
  the experimental WebSocket listener. Standard input/output are newline-delimited JSON-RPC; stderr
  is bounded diagnostic evidence and never forwarded raw to the browser.
- The executable path is host configuration (`Codex:ExecutablePath`, default `codex`). The repository
  root is resolved once from host configuration or the nearest ancestor containing `AGENTS.md` and
  `.git`; the browser supplies neither. Existing Codex authentication/configuration remains owned by
  the Codex CLI and no token or credential enters SQLite.
- Every thread start/resume and turn start supplies the fixed repository root, approval policy
  `never`, and read-only sandbox. Turn policy is `{type:"readOnly",networkAccess:false}` for the
  pinned schema. That pinned schema does not expose the newer restricted read-root option, so this
  slice guarantees no Codex writes and no Codex network access but does not claim OS-level isolation
  of reads outside the working directory. No app-server shell-command API is implemented.
- Any server request for command, file, permission, tool input/call, MCP elicitation, token refresh,
  attestation, or a legacy approval is denied as an unsupported request and makes the turn fail
  closed. Slice 8 never presents an approval control.
- At most two Codex turns run concurrently, initialization is bounded to 10 seconds, each JSON line
  to 256 KiB, agent replies/messages to 8,000 characters, activity summaries to 500 characters, and
  a turn to ten minutes. Queues are bounded and cancellation never silently resends input.

## Persistence and transaction contract

The existing provider-neutral assistant schema gains nullable `ExternalThreadId` on a conversation,
nullable `ExternalTurnId` and `ExternalStatus` on a turn, plus immutable
`assistant_turn_activity` rows: bounded ID, conversation/turn FKs, external item ID, sequence, kind,
status, summary, and timestamp. External item IDs are unique per turn. The confirmed EF migration is
`20260824115228_CodexConversationBridge`.

The existing begin/idempotency transaction remains the durable call claim. After app-server returns
IDs, one transaction binds them to that conversation/turn and rejects mismatches. Completed command,
file-change, MCP-tool, dynamic-tool, web-search, and error/warning summaries append idempotently; raw
command output, patches, hidden reasoning, and protocol frames are not stored. The authoritative
completed agent-message item becomes the visible assistant reply.

An app-server terminal `completed`, `interrupted`, or `failed` event reconciles the durable turn.
Process/JSON/protocol/timeout failure marks it failed with a stable code. Explicit cancellation sends
`turn/interrupt` once and reconciles interruption as cancelled. Host startup converts any leftover
pending/running Codex turn to failed `CODEX_PROCESS_INTERRUPTED`, retaining its external thread ID so
the next user-authored turn explicitly resumes that thread; it never replays the old prompt.

## HTTP and stream contract

- `GET /api/control/assistants/codex/status` uses `control.read` and reports ready/unavailable,
  pinned/observed version, fixed working-directory display path, read-only/no-network policy, and a bounded
  remediation message. It exposes no credential/config content.
- Existing list/detail routes accept provider `codex` and remain operator-scoped.
- Existing create/send routes accept Codex. Codex success responses are bounded
  `application/x-ndjson`: `accepted` (durable IDs/document), zero or more `delta` and `activity`
  events, then exactly one `completed` document. Local-provider JSON behavior is unchanged.
- `POST /api/control/conversations/{conversationId}/turns/{turnId}/cancel` uses
  `control.ai.message`; it can only interrupt that operator's currently registered Codex turn and
  returns accepted/409/404 without waiting for a second provider call.

All routes retain the Slice 0 Host/Origin/identity/capability/rate-limit/no-store boundary. Browser
disconnect requests interruption; durable terminal reconciliation uses a non-request cancellation
token. The UI identifies Codex as repository read-only, streams visible agent text and activity,
supports explicit cancel, and offers a new user-authored turn after failure/interruption. It contains
no approval, permission, network, model, path, system-prompt, or autonomous-run control.
